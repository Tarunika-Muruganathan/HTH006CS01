# DATASET_README.md

Synthetic enterprise activity-log dataset for insider-threat detection 
(hackathon problem HTH-CS-07). Generated by `gen_dataset_v2.py`, deterministic for a given seed.

## Parameters
- users: 2500
- days: 180 (period: 2026-01-05 to 2026-07-03)
- baseline_days: 40 (days 0-39 are guaranteed free of malicious/decoy labels)
- seed: 2027
- resources: 700 files

## Scenario definitions
**Malicious (is_malicious=1):**
- M1 compromised_account: new country + off-hours + sensitive files (subtle variant: new country, normal hours, 8-15 files)
- M2 exit_exfiltration: escalating downloads of own-dept Confidential/Restricted + USB + external upload; resignation_notice present for ~2/3 of instances
- M3 privilege_creep: low-and-slow drift into another department over 30-45 days, rising sensitivity
- M4 impossible_travel: concurrent overlapping sessions from two distant countries
- M5 data_staging_email: many email_attachment events on Confidential/Restricted files over 3-5 days, no USB, read volume near normal
- M6 sabotage: burst of deletes on own-dept files, partly off-hours, then back to normal
- M7 credential_sharing: a second device active in the same country with sessions overlapping the primary device, over several weeks

**Decoys (is_malicious=0):** business_travel, on_call_night_work, quarter_close_spike, weekend_deadline, 
new_hire_onboarding, legit_role_change, remote_relocation. Plus performance_review HR noise scattered on random users (not tied to any scenario).

## Assumptions & design notes
- All malicious/decoy scenario windows start after `baseline_days`, so the baseline window is clean by construction.
- No user appears in more than one scenario (malicious or decoy). Benign behavioral drift (~10% of users: gradual work-hour shift, or a growing share of accesses to a second department) is drawn only from the remaining non-scenario pool.
- `labels_user_day.csv` labels only the specific days on which a scenario actually generated events (not every calendar day inside a scenario's start/end window), per the 'label only meaningfully abnormal days' rule.
- Sessions never cross midnight and never overlap on the same device, except where a scenario intends it (M4 impossible travel, M7 credential sharing use different devices). Extra scenario activity on a day the user already worked is layered *inside* the existing session.
- Anti-leakage: user IDs, device IDs and file IDs are random alnum tokens drawn from one shared generator used identically for normal and malicious entities; attacker devices/IPs are generated with the same function as ordinary secondary devices/IPs, so no naming pattern separates the two populations.
- Run `python3 gen_dataset_v2.py --validate --out <dir>` (or `python3 validate.py <dir>`) to check schema, integrity, session consistency, baseline cleanliness and per-scenario signal presence.

## Known limitations
- Business-travel 'familiar vs. novel destination' is recorded as a 50/50 flag in the scenario description text, but no explicit prior-visit history is separately modeled in the events themselves.
- Timezone effects on local off-hours are simplified: 'off-hours' is evaluated against the user's own clock, not destination-local time.
- Sensitivity-mix percentages are close to, but not exactly, the target weights, since resource counts are randomly sampled per department.
